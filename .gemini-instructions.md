# SDR_Pi Project Instructions

## Project Context

- Passive radar and radio monitoring system for UAV detection based on Raspberry Pi and Pluto SDR.
- Tech Stack: Python 3, PyQt6 (GUI), asyncio/qasync, NumPy (DSP & Math).

## Coding & Testing Rules

- Enforce strict PEP 484 typing. Always use `-> None` for empty functions. Do not use `# type: ignore` unless absolutely necessary.
- Use `pytest` for unit testing.
- Never test real physical hardware (Pluto SDR, GPS) in unit tests. Always mock hardware dependencies using `unittest.mock`.
- Use `pytest-qt` and `qtbot` fixtures for all GUI tests.
- Strictly follow the AAA (Arrange, Act, Assert) testing pattern.

## Agentic Tools & Automated Checks (CRITICAL)

- You have permission to execute local linting, formatting, and testing commands to verify your changes.
- **Before marking any task as complete** or proposing code changes, you **MUST run**:
  1. `make format` — to automatically style and format the code according to PEP 8.
  2. `make fix` — to automatically resolve basic code style issues.
  3. `make check` — to ensure there are no strict typing (MyPy), linting (Ruff), or dependency (Deptry) violations.
- **When creating or modifying test files**, you **MUST immediately run `pytest`** on the newly created test file to verify its correctness.
- Do not consider a test complete until it passes successfully. If a test fails, refactor it and rerun `pytest` until it is completely green.

## Language Requirements (CRITICAL)

- Write all code comments, docstrings, and generated documentation strictly in **Ukrainian**.
- Generate Git commit messages in **Ukrainian** following the Conventional Commits format (e.g., "feat: додано новий парсер", "fix: виправлено відображення спектра").
