# SDR Pi - Система Виявлення Цілей 📡

**SDR Pi** — це клієнтська частина системи радіомоніторингу (UI), розроблена на Python (PyQt6). Додаток приймає дані від аналізатора спектру (Raspberry Pi), детектує та візуалізує цілі, виявлені на радіочастотах.

> **Архітектура:** Цей репозиторій містить UI. Логіка аналізу спектру та відповідіні модулі (зараз знаходяться в папці `temp`) згодом будуть винесені в окремий сервіс на Raspberry Pi.

---

## 🎯 Основні можливості

- **Детекція цілей** — відображення радіочастотних об'єктів в реальному часі
- **Відстеження** — моніторинг переміщення та змін параметрів виявлених цілей
- **Мережева комунікація** — отримання даних від SDR-аналізатора через TCP/IP
- **Локальна база даних** — даних про об'єкти для детектування (SQLite)

## ⚙️ Встановлення та Налаштування

### 0. Склонуйте репозиторій

```bash
# Клонування репозиторію
git clone <url>

# Перехід до папки проєкту
cd SDR_Pi
```

### 1. Створення віртуального оточення

Створіть та активуйте віртуальне середовище `.venv`:

```bash
# Створення (один раз)
python -m venv .venv

# Активація (для Windows Git Bash):
source ./.venv/Scripts/activate

# Активація (для Linux/macOS):
source .venv/bin/activate
```

### 2. Встановлення залежностей

Проект використовує `pip-tools` для синхронізації версій пакетів.

```bash
# 1. Встановлюємо інструмент pip-tools
pip install pip-tools

# 2. Скомпілюємо залежності до requirements.txt
pip-compile

# 3. Синхронізуємо залежності з файлу requirements.txt
pip-sync
```

### 3. Налаштування конфігурації

У корені проекту знайдіть файл `config.ini`. Відкрийте його та вкажіть IP-адресу вашого пристрою (або адресу, де запущено симуляцію/сервер):

```ini
[pinetwork]
# Приклад налаштування (замініть на IP іншої raspberry або того пристрою на якому буде запускатися симуляція)
pi_target_ip = 192.168.1.X
```

## 🚀 Запуск (Development Mode)

Для локального запуску та тестування без реального заліза використовується симулятор (`dummy_sender`) та локальна база даних SQLite.

**Рекомендований порядок запуску** (використовуйте різні вкладки терміналу):

### Крок 1: Підготовка БД (одноразово або при зміні моделей)

Скрипт наповнює локальну SQLite базу тестовими даними. (Не забудьте активувати venv!)

```bash
python -m temp.populate_db_util
```

### Крок 2: Запуск симуляції (Dummy Sender)

Цей скрипт емулює роботу віддаленого Raspberry Pi, надсилаючи фіктивні дані про цілі в додаток.

```bash
python -m app.utils.dummy_sender
```

### Крок 3: Запуск головного додатку (UI)

Запускає графічний інтерфейс користувача.

```bash
py main.py
# Або:
python main.py
```

---

### Робота з реальним обладнанням

1. Переконайтеся, що Raspberry Pi з SDR-аналізатором запущений та доступний в мережі
2. Вкажіть правильну IP-адресу в `config.ini`
3. Запустіть тільки головний застосунок:

```bash
source ./.venv/Scripts/activate
python main.py
```

│   ├── ui/                     # .ui файли та згенеровані .py
│   │   └── components/         # Рендерери (SpectralRenderer, RadarRenderer)

│   ├── protocols.py            # Визначення інтерфейсів (Protocol) та типів
│   └── resources.qrc           # Файл ресурсів Qt
├── logs/                       # Папка логів
│   ├── backgrounds/            # Важкі дані фону (.jsonl)
│   └── session_*.jsonl         # Основні логи подій
├── media/                      # Папка для збережених записів/скріншотів

│   ├── populate_db_util.py     # Скрипт генерації тестової БД
│   ├── database_service.py     # Робота з SQLite
│   ├── pi_server_service.py    # Серверна логіка іншої распберрі
│   ├── run_server.py           # Скрипт запуску сервера

### Про папку `temp/`

Містить модулі для іншої raspberry. Ці структури згодом будуть перенесені в окремий репозиторій для Raspberry Pi (серверна частина).

## 🔧 База даних

Проект використовує **SQLite** для зберігання даних про об'єкти для можливості детектування:

- **У розробці:** локальна БД в папці `temp/` (створюється через `populate_db_util.py`)
- **У продакшені:** БД знаходиться на Raspberry Pi, клієнт отримує дані через мережу

## 🛠 Вирішення типових проблем

### `ModuleNotFoundError`

Переконайтеся, що ви запускаєте скрипти з кореневої папки проекту (де лежить `main.py`) і використовуєте прапорець `-m` для модулів:

```bash
# Правильно ✅
python -m temp.populate_db_util

# Неправильно ❌
python temp/populate_db_util.py
```

### Немає з'єднання

Перевірте `config.ini`. IP-адреса має відповідати тій машині, де запущено `dummy_sender` (якщо тестуєте локально — це `localhost` або ваш локальний IP).

### Проблеми з БД

База даних — це SQLite (файл у папці `temp` для тестів). Якщо потрібно, очистіть файл БД і перезапустіть `populate_db_util`.

### Застосунок не запускається

```bash
# Перевірте, чи активовано віртуальне оточення
which python  # Має показувати шлях до .venv

# Переконайтеся, що всі залежності встановлені
pip-sync
```
