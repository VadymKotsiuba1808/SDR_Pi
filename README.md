# SDR Pi — Система Виявлення Цілей 📡

**SDR Pi** — це клієнтська частина системи радіомоніторингу (UI), розроблена на Python (PyQt6). Додаток приймає дані від аналізатора спектру (Raspberry Pi), детектує та візуалізує цілі, виявлені на радіочастотах.

> **Архітектура:** Цей репозиторій містить UI. Логіка аналізу спектру та відповідні модулі (зараз знаходяться в папці `temp`) згодом будуть винесені в окремий сервіс на Raspberry Pi.

---

## 🎯 Основні можливості

- **Детекція цілей** — відображення радіочастотних об'єктів в реальному часі
- **Відстеження** — моніторинг переміщення та змін параметрів виявлених цілей
- **Мережева комунікація** — отримання даних від SDR-аналізатора через TCP/IP
- **Локальна база даних** — даних про об'єкти для детектування (SQLite)

## ⚙️ Встановлення та Налаштування

### 0. Клонування репозиторію

```bash
git clone <url>
cd SDR_Pi
```

### 1. Створення віртуального оточення

```bash
# Створення (один раз)
python -m venv .venv

# Активація — Windows (Git Bash)
source ./.venv/Scripts/activate

# Активація — Linux / macOS
source .venv/bin/activate
```

### 2. Встановлення залежностей

Проект використовує `pip-tools` для управління залежностями та `Makefile` для спрощення команд.

```bash
# Встановлення pip-tools
pip install pip-tools

# Встановлення всіх залежностей (production + dev)
make deps
```

### 3. Налаштування конфігурації

Відкрийте файл `config.ini` у корені проекту та вкажіть IP-адресу вашого пристрою (або адресу, де запущено симуляцію/сервер):

```ini
[pinetwork]
# Замініть на IP вашої Raspberry Pi або пристрою із симуляцією
pi_target_ip = 192.168.1.X
```

## 🚀 Запуск (Development Mode)

Для локального запуску та тестування без реального заліза використовується симулятор (`dummy_sender`) та локальна база даних SQLite.

> Рекомендується використовувати окремі вкладки терміналу для кожного кроку.

### Крок 1 — Підготовка БД _(одноразово або при зміні моделей)_

Скрипт наповнює локальну SQLite базу тестовими даними. Не забудьте активувати `.venv`!

```bash
python -m temp.populate_db_util
```

### Крок 2 — Запуск симуляції (Dummy Sender)

Цей скрипт емулює роботу віддаленого Raspberry Pi, надсилаючи фіктивні дані про цілі в додаток.

```bash
python -m app.utils.dummy_sender
```

### Крок 3 — Запуск головного додатку

Запускає графічний інтерфейс користувача.

```bash
python main.py
# або
py main.py
```

### Робота з реальним обладнанням

1. Переконайтеся, що Raspberry Pi з SDR-аналізатором запущений та доступний у мережі
2. Вкажіть правильну IP-адресу в `config.ini`
3. Запустіть лише головний застосунок:

```bash
source ./.venv/Scripts/activate
python main.py
```

## 🛠 Розробка та Контроль Якості

Усі налаштування лінтерів знаходяться у файлі `pyproject.toml`.

### Makefile — швидкі команди

| Команда      | Опис                                                                        |
| ------------ | --------------------------------------------------------------------------- |
| `make check` | Запуск усіх перевірок: Ruff (лінтер), MyPy (типізація), Deptry (залежності) |
| `make fix`   | Автоматичне виправлення стилістичних помилок та сортування імпортів         |
| `make deps`  | Компіляція та встановлення нових пакетів                                    |

> Введіть `make` у терміналі, щоб побачити повний список доступних команд.

### Pre-commit Hooks

Перед початком розробки ініціалізуйте локальний захист комітів:

```bash
pre-commit install
```

Це автоматично перевірятиме код перед кожним `git commit`.

> **⚠️ Екстрений пропуск (Bypass):** Якщо трапилася критична ситуація (гарячий фікс) і вам потрібно терміново зберегти коміт, проігнорувавши помилки лінтера, додайте прапорець `--no-verify` (або `-n`):
>
> ```bash
> git commit -m "Urgent hotfix" --no-verify
> ```

### CI/CD (GitHub Actions)

Налаштовано автоматичний пайплайн. При кожному пуші код проходить сувору перевірку — коміт буде відхилено у разі критичних синтаксичних помилок або проблем з імпортами.

### Додавання нових залежностей

Якщо вам потрібно додати нову бібліотеку:

1. Додайте її назву у `requirements.in` (production) або `requirements-dev.in` (dev-інструменти)
2. Виконайте:

```bash
make deps
```

## 🔧 База даних

Проект використовує **SQLite** для зберігання даних про об'єкти для можливості детектування:

- **Розробка:** локальна БД у папці `temp/` — створюється через `populate_db_util.py`
- **Продакшен:** БД знаходиться на Raspberry Pi, клієнт отримує дані через мережу

## 🛠 Вирішення типових проблем

### `ModuleNotFoundError`

Переконайтеся, що ви запускаєте скрипти з кореневої папки проекту (де лежить `main.py`) і використовуєте прапорець `-m` для модулів:

```bash
# ✅ Правильно
python -m temp.populate_db_util

# ❌ Неправильно
python temp/populate_db_util.py
```

### Немає з'єднання

Перевірте `config.ini`. IP-адреса має відповідати тій машині, де запущено `dummy_sender` (якщо тестуєте локально — це `localhost` або ваш локальний IP).

### Проблеми з БД

База даних — це SQLite (файл у папці `temp/` для тестів). Якщо потрібно — видаліть файл БД і перезапустіть `populate_db_util`.

### Застосунок не запускається

```bash
# Перевірте, чи активовано віртуальне оточення
which python  # Має вказувати на .venv

# Синхронізуйте залежності
make sync
```
