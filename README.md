# SDR Pi — Система Виявлення Цілей 📡

**SDR Pi** — це професійна клієнтська частина системи радіомоніторингу (**Модуль Оператора**), розроблена на Python (PyQt6). Додаток приймає дані від аналізатора спектру (Raspberry Pi + Pluto SDR), детектує, візуалізує та аналізує цілі, виявлені у радіоефірі та акустичному фоні.

> **Архітектура:** Цей репозиторій містить інтерфейс та логіку управління. Модуль аналізу сигнатур та серверна частина (знаходяться в папці `pi_server`) забезпечують зв'язок з реальним апаратним забезпеченням.

## 🎯 Основні можливості

- **Детекція та Відстеження** — відображення РЧ-об'єктів у реальному часі на радарній сітці та мапі.
- **Керування реле (Jammer)** — дистанційна активація апаратних виходів та налаштування груп реле.
- **Моніторинг спектру** — перегляд живих FFT та Waterfall діаграм для виявлення завад.
- **Глибока Аналітика** — перегляд траєкторій руху, рівнів сигналу та хронології подій у журналі.
- **Медіа-фіксація** — створення скріншотів та фоновий відеозапис екрану у форматі MP4.
- **Багатомовність** — повна підтримка української та англійської мов з перемиканням "на льоту".
- **Безпека** — рольова модель (Operator/Owner) та скидання пароля через фізичний USB-ключ.

## ⚙️ Встановлення та Налаштування

### 0. Клонування репозиторію

```bash
git clone <url>
cd SDR_Pi
```

### 1. Створення віртуального оточення

```bash
# Створення (один раз)
python -m venv .venv

# Активація — Windows (Git Bash)
source ./.venv/Scripts/activate

# Активація — Linux / macOS
source .venv/bin/activate
```

### 2. Встановлення залежностей

Проект використовує `pip-tools` для управління залежностями та `Makefile` для спрощення команд.

```bash
# Встановлення pip-tools
pip install pip-tools

# Встановлення всіх залежностей (production + dev)
make deps
```

### 3. Налаштування конфігурації

Відкрийте файл `config.ini` у корені проекту та вкажіть IP-адресу вашої Raspberry Pi (або адресу симулятора):

```ini
[pinetwork]
pi_target_ip = 192.168.1.X
pi_target_port = 6000
```

## 🚀 Запуск (Development Mode)

Для локального запуску та тестування без реального заліза використовується симулятор (`dummy_sender`) та вбудована серверна частина.

> Рекомендується використовувати окремі вкладки терміналу для кожного кроку.

### Крок 1 — Підготовка БД _(одноразово або при зміні моделей)_

Скрипт наповнює локальну SQLite базу тестовими сигнатурами.

```bash
python -m pi_server.populate_db_util
```

### Крок 2 — Запуск симуляції (Dummy Sender)

Цей скрипт емулює роботу віддаленого Raspberry Pi, надсилаючи дані про цілі в додаток.

```bash
python -m app.utils.dummy_sender
```

### Крок 3 — Запуск головного додатку

Запускає графічний інтерфейс Модуля Оператора.

```bash
python main.py
```

### Робота з реальним обладнанням

1. Переконайтеся, що Raspberry Pi з SDR-аналізатором запущений та доступний у мережі.
2. Вкажіть правильну IP-адресу в `config.ini`.
3. Запустіть лише головний застосунок: `python main.py`.

## 🛠 Розробка та Контроль Якості

Ми використовуємо професійний набір інструментів для підтримки стабільності системи. Усі налаштування лінтерів знаходяться у файлі `pyproject.toml`.

### Makefile — швидкі команди

| Команда         | Опис                                                           |
| :-------------- | :------------------------------------------------------------- |
| `make check`    | Ruff (лінтер), MyPy (типізація), Deptry (залежності)           |
| `make test`     | Запуск **264 автоматизованих тестів** (Unit, Integration, E2E) |
| `make coverage` | Вимірювання покриття коду (поточне значення **~73%**)          |
| `make fix`      | Автоматичне виправлення помилок стилю та імпортів              |
| `make docs`     | Запуск локального сервера документації                         |
| `make deps`     | Компіляція та встановлення нових пакетів                       |

> Введіть `make` у терміналі, щоб побачити повний список доступних команд.

### Pre-commit Hooks

Перед початком розробки ініціалізуйте локальний захист комітів:

```bash
pre-commit install
```

Це автоматично перевірятиме код перед кожним `git commit`.

> **⚠️ Екстрений пропуск (Bypass):** Якщо трапилася критична ситуація (гарячий фікс) і вам потрібно терміново зберегти коміт, проігнорувавши помилки лінтера, додайте прапорець `--no-verify` (або `-n`):
>
> ```bash
> git commit -m "Urgent hotfix" --no-verify
> ```

### CI/CD (GitHub Actions)

При кожному `push` у репозиторій автоматично запускається пайплайн:

1. **Static Analysis:** Перевірка синтаксису, форматування та типів.
2. **Automated Testing:** Повний прогін тестів у віртуальному GUI-оточенні (`xvfb`).
3. **Docs Deployment:** Автоматичне оновлення онлайн-документації.

### Додавання нових залежностей

Якщо вам потрібно додати нову бібліотеку:

1. Додайте її назву у `requirements.in` (production) або `requirements-dev.in` (dev-інструменти)
2. Виконайте:

```bash
make deps
```

## 🔧 База даних

Проект використовує **SQLite** для зберігання сигнатур об'єктів:

- **Розробка:** локальна БД у папці `pi_server/` — створюється через `populate_db_util.py`.
- **Продакшен:** БД знаходиться на Raspberry Pi, клієнт отримує дані через TCP.

## 🛠 Вирішення типових проблем

### `ModuleNotFoundError`

Використовуйте прапорець `-m` та запускайте з кореня:
`python -m pi_server.populate_db_util`

### Немає з'єднання

Перевірте `config.ini`. IP-адреса має відповідати тій машині, де запущено `dummy_sender` (якщо тестуєте локально — це `localhost` або ваш локальний IP).

### Проблеми з БД

База даних — це SQLite (файл у папці `pi_server/` для тестів). Якщо потрібно — видаліть файл БД і перезапустіть `populate_db_util`.

### Проблеми з відображенням GUI в тестах

Для запуску тестів, що потребують графіки, на Linux-серверах використовується `xvfb-run`.

### Скидання пароля

Якщо ви забули пароль Власника, скористайтеся USB-ключем безпеки (детальніше у розділі "Безпека" документації).

### Застосунок не запускається

```bash
# Перевірте, чи активовано віртуальне оточення
which python  # Має вказувати на .venv

# Синхронізуйте залежності
make sync
```
