# Архітектура Системи

Програмний комплекс **SDR_Pi** розроблений для забезпечення керування, збереження та візуалізації даних у системі пасивного радарного та радіомоніторингу (детекції БПЛА).

Комплекс логічно та фізично розділений на два основні вузли, які з'єднані безпосередньо через Ethernet-кабель. Це забезпечує мінімальну затримку (latency) та незалежність від зовнішньої мережевої інфраструктури.

!!! note "Призначення репозиторію"
    **Ця документація описує Модуль Клієнта (Інтерфейс) та базові заглушки Сервера.** 
    Директорія `pi_server/` у цьому проекті містить серверний код (TCP, SQLite), який передається колегам для розгортання на Raspberry Pi. У межах цього репозиторію він використовується переважно для повноцінного E2E-тестування клієнтського додатку в умовах, максимально наближених до реальних.

## Основні компоненти системи

### 1. Обчислювальний модуль (Сервер на Raspberry Pi)
Це "мозок" системи, що працює в полях. Він виконує всю важку математику та апаратну взаємодію.

*   **Апаратний рівень:** Фізично підключені модулі: SDR (для аналізу радіочастот), мікрофони (акустичний аналіз), модуль GPS (позиціонування) та керовані виходи (системи РЕБ / Jammer, реле).
*   **База даних сигнатур (SQLite):** Зберігає еталонні сигнатури різних класів БПЛА.
*   **Модуль аналізу (DSP):** Отримує сирі сигнали з антен/мікрофонів, завантажує сигнатури з БД та виконує порівняння. Якщо знайдено збіг — формує пакет даних.
*   **TCP Сервер (`pi_server`):** Напряму передає клієнту результати аналізу (без очікування додаткових запитів від клієнта) та приймає команди керування (наприклад, увімкнути РЕБ).

### 2. Модуль Керівника (Клієнт на ПК)
Десктопний додаток на базі PyQt6, який отримує оброблені дані та надає оператору зручний інтерфейс для моніторингу та керування.

*   **Мережевий рівень (`PiNetworkService`):** Слухає Ethernet-з'єднання. Десеріалізує вхідні JSON-пакети від Raspberry Pi у внутрішні моделі (Pydantic/Dataclass).
*   **Бізнес-логіка та Сховище:** 
    *   Обробляє отримані дані (відображення на мапі, графіках).
    *   **Локальні журнали (Logs):** Наразі вся історія виявлень та дій оператора зберігається локально у форматі `JSONL`. В майбутньому планується міграція на локальну базу даних для складнішої аналітики.
*   **Рівень UI (`app/widgets/`):** Візуалізація даних. Динамічні графіки спектру, інтерактивна мапа (позиція прив'язується до GPS-даних від сервера) та панелі керування Jammer-ом.

## Життєвий цикл детекції (Data Flow)

Ось як інформація проходить через систему:

1.  **Захоплення та Аналіз (Сервер):** Raspberry Pi зчитує частоти з SDR. Аналізатор порівнює їх з еталонними сигнатурами зі своєї SQLite БД.
2.  **Виявлення:** При збігу сигнатур Сервер одразу формує JSON-пакет (`DetectionEvent`), що містить тип об'єкта, частоту та поточні GPS-координати.
3.  **Передача:** Пакет миттєво відправляється по Ethernet-кабелю до Клієнта.
4.  **Візуалізація та Логування (Клієнт):** 
    *   `PiNetworkService` приймає пакет.
    *   UI оновлюється: на мапі з'являється маркер, графіки оновлюють спектр.
    *   Подія записується у локальний `JSONL` файл історії.
5.  **Реакція (Опціонально):** Оператор через UI натискає кнопку активації РЕБ. Клієнт відправляє TCP-команду на Сервер, який фізично замикає реле або активує Jammer.
