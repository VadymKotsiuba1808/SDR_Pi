# Тестування та CI/CD

Проект **SDR_Pi** розроблявся із застосуванням практик **Test-Driven Development (TDD)** та безперервної інтеграції (CI). Це гарантує стабільність системи при роботі з реальним SDR-обладнанням.

---

## 📊 Статистика покриття (Coverage)

Всі тести знаходяться у папці **`tests/`**.
На даному етапі проект має наступні показники якості:
*   **Загальна кількість тестів:** 264
*   **Загальне покриття коду (Line Coverage):** ~73%
*   **Основні модулі (Models, Core, Utils):** Покриття 100%

*Примітка: Файл `.coverage` містить бінарні результати останнього аналізу, на основі яких генеруються HTML-звіти.*

---

## 🚀 CI/CD Пайплайн (GitHub Actions)

При кожному `push` або `pull_request` у будь-яку гілку автоматично запускається багаторівневий пайплайн:

### Етап 1: Static Analysis
Це "швидкий" етап, який блокує злиття коду при наявності критичних помилок (детальніше про лінтери див. у розділі [Якість та Стандарти](quality.md)):
*   **Hard Fail:** Синтаксичні помилки, невикористані змінні, порушення форматування.
*   **Soft Fail:** Поради MyPy та другорядні зауваження лінтера (відображаються як попередження).

### Етап 2: Automated Tests
Запускається лише після успішного проходження першого етапу. Виконує повний прогін 264 тестів у віртуальному графічному оточенні (`xvfb`) та генерує звіт про покриття.

!!! success "Артефакти CI"
    Після кожного прогону на GitHub зберігається **HTML Coverage Report**, який можна завантажити та проаналізувати.
