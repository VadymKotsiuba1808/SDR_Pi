# Тестування та Якість Коду

Проект **SDR_Pi** розроблявся із застосуванням практик **Test-Driven Development (TDD)** та безперервної інтеграції (CI). Це гарантує стабільність системи при роботі з реальним SDR-обладнанням.

---

*   **Загальна кількість тестів:** 264
*   **Загальне покриття коду (Line Coverage):** ~73%
*   **Основні модулі (Models, Core, Utils):** Покриття 100%

---

## 🔍 Статичний аналіз та Стандарти

Для забезпечення високої якості коду та відповідності стандартам PEP 8 та PEP 484, у проекті використовуються наступні інструменти:

### 1. Ruff (Форматування та Лінтинг)
`Ruff` — це надшвидкий інструмент для перевірки коду. Він замінює Flake8, isort та Black.
*   **Команда:** `make check` (виконує повний цикл перевірок).
*   **Автофікс:** `make fix` дозволяє автоматично виправити більшість дрібних помилок стилю.

### 2. MyPy (Перевірка типів)
Проект використовує сувору типізацію. `MyPy` перевіряє відповідність анотацій типів, що дозволяє виявити помилки до моменту запуску програми.

### 3. Deptry (Залежності)
Перевіряє `requirements.in` на наявність зайвих або пропущених бібліотек, що допомагає підтримувати чистоту оточення.

## 🚀 CI/CD Пайплайн (GitHub Actions)

При кожному `push` або `pull_request` у будь-яку гілку автоматично запускається багаторівневий пайплайн:

### Етап 1: Static Analysis
Це "швидкий" етап, який блокує злиття коду при наявності критичних помилок:
*   **Hard Fail:** Синтаксичні помилки, невикористані змінні, порушення форматування.
*   **Soft Fail:** Поради MyPy та другорядні зауваження лінтера (відображаються як попередження).

### Етап 2: Automated Tests
Запускається лише після успішного проходження першого етапу. Виконує повний прогін 264 тестів у віртуальному графічному оточенні (`xvfb`) та генерує звіт про покриття.
