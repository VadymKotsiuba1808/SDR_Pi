    Якість та Стандарти Розробки

    Проект SDR_Pi розроблений із дотриманням сучасних стандартів інженерії програмного забезпечення. У цьому розділі описані інструменти та конфігураційні файли, які забезпечують стабільність, чистоту коду та автоматизацію процесів.

    🛠 Автоматизація (Makefile)

    Для спрощення щоденних операцій та стандартизації середовища розробки використовується файл Makefile. Він дозволяє виконувати складні команди одним коротким записом.

    • make deps: Повна синхронізація віртуального оточення із зафіксованими версіями пакетів.
    • make check: Комплексна перевірка коду (лінтер + типізація).
    • make test: Запуск усього набору тестів.
    • make coverage: Аналіз покриття коду тестами.
    • make format: Автоматичне виправлення помилок стилю.

    📏 Стандарти коду та Лінтери

    Ми використовуємо набір інструментів для підтримки коду в хорошому стані, конфігурація яких зосереджена у файлі pyproject.toml.

    1. Ruff (Форматування та Лінтер)

    Використовується для автоматичної перевірки синтаксису, видалення невикористаних імпортів та форматування коду згідно з PEP 8. Це гарантує, що весь код проекту виглядає так, ніби його написала одна людина.

    2. MyPy (Статична типізація)

    Проект має сувору типізацію (PEP 484). MyPy аналізує код без його запуску та попереджає про потенційні помилки невідповідності типів даних, що критично для надійності радарної системи.

    3. Deptry (Залежності)

    Перевіряє requirements.in на наявність зайвих або пропущених бібліотек, що допомагає підтримувати чистоту оточення.

    4. Pre-commit hooks

    У файлі .pre-commit-config.yaml налаштовані автоматичні перевірки, які запускаються при кожній спробі зробити git commit. Система не дозволить зафіксувати зміни, якщо:

    • У коді є синтаксичні помилки.
    • Присутні "забруднені" імпорти (автоматично виправляє ruff).

    📦 Управління залежностями

    Замість прямого використання pip install, ми використовуємо pip-tools для гарантування відтворюваності збірки:

    • requirements.in: Містить лише назви основних бібліотек.
    • requirements-dev.in: Інструменти для розробки та тестування.
    • requirements.txt: Автоматично згенерований файл із жорстко зафіксованими версіями (hashes) усіх бібліотек та їхніх залежностей. Це гарантує, що проект запуститься через рік так само успішно, як і сьогодні.

    🏗 Ресурси та Конфігурація UI

    Qt Project та Ресурси

    • app.pro: Файл проекту Qt, що описує структуру вікон та ресурсів.
    • resources.qrc: XML-файл, який перераховує всі іконки та стилі.
    • app/assets/resources_rc.py: Згенерований Python-код, який "зашиває" всі картинки прямо в бінарний код додатку, що спрощує дистрибуцію (не потрібно тягати за собою сотні PNG-файлів).

    Конфігурація системи

    • config.ini: Головний файл налаштувань, який зчитується SettingsService. Він розділений на секції ([pinetwork], [ui], [maps]), що дозволяє легко змінювати параметри системи без перекомпіляції коду.

    🚀 Точка входу (main.py)

    Файл main.py є центральним вузлом запуску. Його основні обов'язки:

    1. Ініціалізація циклу подій asyncio через qasync.
    2. Завантаження налаштувань та локалізації.
    3. Створення спільних екземплярів сервісів (Dependency Injection).
    4. Запуск головного вікна та підключення до мережі Raspberry Pi.
